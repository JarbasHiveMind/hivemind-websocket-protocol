# AGENTS.md — `hivemind-websocket-protocol`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

This is the reference websocket network transport for HiveMind: it is the
`NetworkProtocol` plugin that [hivemind-core](https://github.com/JarbasHiveMind/HiveMind-core)
loads at runtime under the `hivemind.network.protocol` entry-point group (name
`hivemind-websocket-plugin`), via hivemind-plugin-manager's `NetworkProtocolFactory`.
It is the default transport, started with no explicit config when `server.json`
gives it none. Part of the [HiveMind](https://github.com/JarbasHiveMind) ecosystem —
a protocol for connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). Related repos: HiveMind-core (the hub
that loads this plugin), hivemind-plugin-manager (the entry-point loader and shared
`NetworkProtocol` base), hivemind-bus-client (the client library that speaks this
wire protocol), hivescope (the in-process test harness used by the e2e suite).

## Layout / build / test

- Package module: `hivemind_websocket_protocol/`. Tests live in `tests/` (unit)
  and `tests/e2e/` (boots a real hub via hivescope) — do not create a second test
  directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest tests -q`.
  The `[test]` extra pins `hivescope>=0.7.1a1` — below that floor, uv resolves
  hivescope 0.6.1a3, whose `InProcessHiveShim` has no `.password` attribute,
  and every e2e test errors at handshake setup. If e2e tests fail on import or
  handshake, check the resolved hivescope version before assuming a code bug.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.

  needed — with a one-line comment saying why. No upper caps unless a specific
  released version is genuinely broken (say which and why).

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test
  that only asserts a mock was called, without asserting the real behaviour, is
  weak — note it.
- Never skip a test because an optional dependency is missing.
- CI green is permission to review, not to merge. A non-trivial change gets an
  adversarial review before it lands.

## Repo-specific rules

- **Wire back-compat is law.** This plugin is loaded by every deployed
  hivemind-core, against every deployed client vintage, over the persistent
  websocket connection. Do not change the frame format, the auth query-string
  handshake, or the `HiveMindWebsocketProtocol` message flow in a way that
  breaks a client built against an older version. If a change is genuinely
  incompatible, it needs a version negotiation path, not a silent break.
- **A refused API key must close 1008, never dangle.** On invalid authorization
  or an invalid/refused key, the connection closes with code 1008 (see
  `self.close(code=1008, ...)` in `hivemind_websocket_protocol/__init__.py`).
  A client that gets anything other than a fast, explicit close will retry
  forever against credentials that can never work — that is the failure mode
  this rule exists to prevent.
- **Admission, receive, and disconnect all run on Tornado's single IOLoop.**
  Every connected peer is served by the same event loop; a slow or blocking
  call in the handshake, message-receive, or `on_close` path delays every
  other peer, not just the one being handled. Keep this path non-blocking:
  avoid synchronous I/O, and keep logging lazy (`log.debug("...%s", x)`, not
  an eagerly-formatted f-string) so it doesn't cost cycles on the hot path
  when the level is disabled.
- **e2e tests need the hivescope floor.** `tests/e2e/` boots a real hub through
  hivescope's `MasterNode`/`single_satellite` scenarios and the in-process
  `InProcessHiveShim`. That shim only grew a `.password` attribute at
  `hivescope>=0.7.1a1`, which `hivemind-core`'s `handle_new_client` reads;
  below the floor every e2e test errors at handshake setup, not at the
  assertion. Never lower this floor to make a resolution failure go away.
- **Never add a new bus message type.** This plugin transports HiveMessage
  frames; it does not define new message types or new wire semantics on its
  own authority.
